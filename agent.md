# Website preferences

- When asked to reduce a video's scale within its container without an explicit value, use `scale: 0.8`. Keep the container aligned to the project grid. This is the default for future requests; preserve other existing scales unless asked to change them.

- Archive projects have no project detail pages or Project details chips. Their thumbnails must not navigate; an optional Visit site chip may link to the external site.

- Work and Playground projects may also omit a detail page. Mark these cards with `data-project-details="false"`, omit thumbnail navigation and Project details chips, and preserve an optional Visit site chip. Pictogram uses this option.

- For unfinished Work or Playground projects, add `data-project-status="in-development"` to the `.card`. This replaces the Project details chip with an accessible “In development” button that shows a toast, including on mobile, and removes thumbnail navigation while preserving optional Visit site links. It also works with `data-project-details="false"`. Remove the status to restore the card's normal details behavior; Archive cards never show a details/status chip. MitWerk, MitWerk VR, and Job Tracker currently use this status.

- In-development chips use gray italic text and an icon-sized clipped loading animation with three quadrilaterals of equal size and color. Alternate their entry directions and stagger their timing so they do not settle on a shared row. Include moments when all three are visible; the middle must never disappear while both outer blocks are visible. Respect reduced-motion preferences with a static icon.

- Collection-tab clicks must let the active icon transfer and label reveal finish; repeated Work, Playground, or Archive clicks during that sequence must not reset it. Archive has its own amber shape and uses the same arrival transition across pages as Work and Playground.

- Preserve the current single-bounce arrival trajectory. Keep the previous All Projects icon visible until the incoming icon contacts it, then knock the old icon downward. Clip the old icon at the icon slot’s bottom edge throughout the transition, so it cannot paint over the padding below.

- Debug mode lives in `dev-mode.js` (`const DEV_MODE = true/false;` at the top) with styles in `dev-mode.css`; there is no UI toggle, so turn it on/off only when asked (`python3 tools/dev_order.py on|off`). While on, the Work and Archive grids show a red "Debug mode" label above the tag group, cards can be dragged or moved with black hover arrows on either side of the thumbnail, thumbnails don't navigate (chips still do), and the header has a "Cancel & leave" button that discards the arrangement and turns debug mode off. The arranged order is a draft that survives refreshes: `python3 tools/dev-server.py` (http://localhost:8000, allowed by the media CORS rules) stores it in `.dev-order.json`. When the user asks to close/exit debug mode (keeping the order), run `python3 tools/dev_order.py apply`, which writes the draft into the HTML card order and sets `DEV_MODE = false`; if there is no draft, the order was likely arranged without the dev server and lives only in that browser. DOM order in the HTML is the listing order; there is no year sorting.

- Floating screens in grid thumbnails share the `--thumb-screen-margin-block` token in `style.css` (`0.0803`, the gap above and below the screen as a share of the thumbnail's width). Desktop screens (MitWerk, Superformula, Flying Squirrels, Schneider, Superfast) match Superformula: the screen is 85% of the thumbnail width (`width: 100%; scale: 0.85`) and keeps its own aspect ratio, and the thumbnail uses `aspect-ratio: 1 / calc(0.85 * h / w + 2 * var(--thumb-screen-margin-block))`. Phone screens (Neurial Grotesk, TL;DR) wrap the video in `<div class="thumb-phone-screen">` inside the thumbnail. The wrapper keeps the thumbnail's ratio by sizing from container units (`height: calc((thumb h / w - 2 * var(--thumb-screen-margin-block)) * 100cqw)`, plus `aspect-ratio` set to the video's own ratio), and rounds the screen with `border-radius`, `overflow: hidden` and a mask; the video just fills it. Don't use thumbnail padding with `height: 100%` (Safari/Firefox ignore that percentage and the gaps disappear), and don't rely on `border-radius` or `clip-path` on the video itself (Safari leaves a playing video's corners square). Apply this to any new floating screen.

- Grid thumbnail corner radii are relative to the thumbnail's width (`cqi`), tuned at a 1270px viewport (Work thumbnail 603px wide). `[data-project-grid] > .card` and its `.card-thumbnail` are `container-type: inline-size` so this resolves. Every thumbnail frame shares `--radius-thumbnail` (`1.393cqi`, 8.4px at 1270) and every floating desktop screen shares `--radius-desktop-screen` (`1.857cqi`, 11.2px before its 0.85 scale). Floating phone screens (Neurial Grotesk, TL;DR) set their own `cqi` radius per card (currently both `4.643cqi`, 28px at 1270); they don't have to match. Don't use rem/px/vw radii on new grid thumbnails or screens.
