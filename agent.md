# Website preferences

- When asked to reduce a video's scale within its container without an explicit value, use `scale: 0.8`. Keep the container aligned to the project grid. This is the default for future requests; preserve other existing scales unless asked to change them. Adventurer's focus highlight (`adventurer-focus(v3).mp4`) is scaled to `1.18` inside `.adventurer-focus-frame` so its phone matches the other highlight videos; the frame stays full column width. The Product thumbnail uses that same scale.

- Archive projects have no project detail pages or Project details chips. Their thumbnails must not navigate; an optional Visit site chip may link to the external site.

- Product and Playground projects may also omit a detail page. Mark these cards with `data-project-details="false"`, omit thumbnail navigation and Project details chips, and preserve an optional Visit site chip. Pictogram uses this option.

- For unfinished Product or Playground projects, add `data-project-status="in-development"` to the `.card`. This replaces the Project details chip with an accessible “In development” button that shows a toast, including on mobile, and removes thumbnail navigation while preserving optional Visit site links. It also works with `data-project-details="false"`. Remove the status to restore the card's normal details behavior; Archive cards never show a details/status chip. Every Product project currently uses this status except Verso, nijimu, Dino, Adventurer, and GVD, along with MitWerk VR.

- Thumbnails of cards without a project page that aren't in development (every Archive card, plus `data-project-details="false"` cards without `data-project-status`) open their media in a fullscreen blurred overlay (`thumbnail-lightbox.js`, `.thumb-lightbox` in `style.css`). It shows the thumbnail's video (resuming at its current time, with the thumbnail paused until close) or the archive sequence's current frame, keeping the thumbnail's corner radius as a share of the media's width (the screen's own radius, else the thumbnail frame's when the media fills it; inset media like the Wu poster stays square). Overlay media is capped at `--lightbox-max-width: 1200px` and `--lightbox-max-height: 800px` (on `.thumb-lightbox`), and also fits within 92vw × 88dvh on smaller screens. Pictogram mirrors its thumbnail canvas, so it keeps the same blue padding. Opening zooms out of the thumbnail; closing scales down slightly and fades in place instead of returning to the card. Chips inside the thumbnail keep their own actions, and debug mode disables the overlay. Currently disabled: the `thumbnail-lightbox.js` script tag is commented out in index.html and archive.html; uncomment it to turn the overlay back on.

- In-development chips use gray italic text and an icon-sized loading animation with three parallelograms of equal size and color (each 0.7em tall, leaning about 20° with a 0.286em-wide face, spaced 0.42em apart for a 0.134em gap, in a 1.4em × 0.7em icon box), standing still side by side with their bottoms on the label's text baseline (the status chip uses `align-items: baseline`). Only their opacity animates: a highlight passes across them left to right (each pulses 0.3 → 1 → 0.3 in a 1.2s cycle, offset by 0.4s). Respect reduced-motion preferences with a static icon.

- Collection-tab clicks must let the active icon transfer and label reveal finish; repeated Product, Playground, or Archive clicks during that sequence must not reset it. Archive has its own amber shape and uses the same arrival transition across pages as Product and Playground.

- Preserve the current single-bounce arrival trajectory. Hold the previous All Projects icon at its exact displayed position, size, and rotation until the incoming icon contacts it, then knock the old icon downward. Clip the old icon at the icon slot’s bottom edge throughout the transition, so it cannot paint over the padding below.

- Debug mode lives in `dev-mode.js` (`const DEV_MODE = true/false;` at the top) with styles in `dev-mode.css`; there is no UI toggle, so turn it on/off only when asked (`python3 tools/dev_order.py on|off`). While on, the Product and Archive grids show a red "Debug mode" label above the tag group, cards can be dragged or moved with black hover arrows on either side of the thumbnail, thumbnails don't navigate (chips still do), each thumbnail shows the project's tags as a stack of light pills in its top-left corner (the same normalized tags the filters use, which `project-filters.js` exposes as `data-tags`), and the header has a "Cancel & leave" button that discards the arrangement and turns debug mode off. The arranged order is a draft that survives refreshes: `python3 tools/dev-server.py` (http://localhost:8000, allowed by the media CORS rules) stores it in `.dev-order.json`. When the user asks to close/exit debug mode (keeping the order), run `python3 tools/dev_order.py apply`, which writes the draft into the HTML card order and sets `DEV_MODE = false`; if there is no draft, the order was likely arranged without the dev server and lives only in that browser. DOM order in the HTML is the listing order; there is no year sorting.

- Floating screens in grid thumbnails share the `--thumb-screen-margin-block` token in `style.css` (`0.0803`, the gap above and below the screen as a share of the thumbnail's width). Desktop screens (Verso, Superformula, Flying Squirrels, Schneider, Superfast) match Superformula: the screen is 85% of the thumbnail width (`width: 100%; scale: 0.85`) and keeps its own aspect ratio, and the thumbnail uses `aspect-ratio: 1 / calc(0.85 * h / w + 2 * var(--thumb-screen-margin-block))`. Phone screens (Neurial Grotesk, TL;DR) wrap the video in `<div class="thumb-phone-screen">` inside the thumbnail. The wrapper keeps the thumbnail's ratio by sizing from container units (`height: calc((thumb h / w - 2 * var(--thumb-screen-margin-block)) * 100cqw)`, plus `aspect-ratio` set to the video's own ratio), and rounds the screen with `border-radius`, `overflow: hidden` and a mask; the video just fills it. Don't use thumbnail padding with `height: 100%` (Safari/Firefox ignore that percentage and the gaps disappear), and don't rely on `border-radius` or `clip-path` on the video itself (Safari leaves a playing video's corners square). Apply this to any new floating screen.

- Product case-study pages (Dino, Schneider, GVD, Adventurer, nijimu, Verso) open with their cover, before the title, framed like the Playground page thumbnail: `.img-casestudy-cover` is a wrapper `div` placed before `.case-study-header`, a full-width 16:9 stage inset by `--page-inline-space` under the nav, with a 0.5rem radius, the media contained (Dino and Adventurer cover-fit their 16:9 art) on a per-page background, and the title starting 30px below it (80px on `.cs-grid` pages). Like Playground thumbnails, it shows immediately instead of scroll-revealing. GVD's cover uses the video's own ratio (`3420 / 2160`) so the stage height fits the recording instead of cropping it to 16:9.

Info-row label/value pairs aren't affected. Headings and info-list labels keep their own styles. Captions (`.floating-caption` text and `figcaption`) match the landing page's card captions (`.card-text`) in size and weight but use Geist: weight 400, normal line height, full opacity, but at 12.75px and in a lighter gray (`--cs-caption-color`, #8C8C8C, instead of the landing page's #666).
