# Website preferences

- When asked to reduce a video's scale within its container without an explicit value, use `scale: 0.8`. Keep the container aligned to the project grid. This is the default for future requests; preserve other existing scales unless asked to change them. Adventurer's focus highlight (`adventurer-focus(v3).mp4`) is scaled to `1.18` inside `.adventurer-focus-frame` so its phone matches the other highlight videos; the frame stays full column width. The Work thumbnail uses that same scale.

- Archive projects have no project detail pages or Project details chips. Their thumbnails must not navigate; an optional Visit site chip may link to the external site.

- Work and Playground projects may also omit a detail page. Mark these cards with `data-project-details="false"`, omit thumbnail navigation and Project details chips, and preserve an optional Visit site chip. Pictogram uses this option.

- For unfinished Work or Playground projects, add `data-project-status="in-development"` to the `.card`. This replaces the Project details chip with an accessible “In development” button that shows a toast, including on mobile, and removes thumbnail navigation while preserving optional Visit site links. It also works with `data-project-details="false"`. Remove the status to restore the card's normal details behavior; Archive cards never show a details/status chip. Every Work project currently uses this status except Verso, Dino, Adventurer, and GVD, along with MitWerk VR.

- Thumbnails of cards without a project page that aren't in development (every Archive card, plus `data-project-details="false"` cards without `data-project-status`) open their media in a fullscreen blurred overlay (`thumbnail-lightbox.js`, `.thumb-lightbox` in `style.css`). It shows the thumbnail's video (resuming at its current time, with the thumbnail paused until close) or the archive sequence's current frame, keeping the thumbnail's corner radius as a share of the media's width (the screen's own radius, else the thumbnail frame's when the media fills it; inset media like the Wu poster stays square). Overlay media is capped at `--lightbox-max-width: 1200px` and `--lightbox-max-height: 800px` (on `.thumb-lightbox`), and also fits within 92vw × 88dvh on smaller screens. Pictogram mirrors its thumbnail canvas, so it keeps the same blue padding. Opening zooms out of the thumbnail; closing scales down slightly and fades in place instead of returning to the card. Chips inside the thumbnail keep their own actions, and debug mode disables the overlay. Currently disabled: the `thumbnail-lightbox.js` script tag is commented out in index.html and archive.html; uncomment it to turn the overlay back on.

- In-development chips use gray italic text and an icon-sized loading animation with three parallelograms of equal size and color (each 0.7em tall, leaning about 20° with a 0.286em-wide face, spaced 0.42em apart for a 0.134em gap, in a 1.4em × 0.7em icon box), standing still side by side with their bottoms on the label's text baseline (the status chip uses `align-items: baseline`). Only their opacity animates: a highlight passes across them left to right (each pulses 0.3 → 1 → 0.3 in a 1.2s cycle, offset by 0.4s). Respect reduced-motion preferences with a static icon.

- Collection-tab clicks must let the active icon transfer and label reveal finish; repeated Work, Playground, or Archive clicks during that sequence must not reset it. Archive has its own amber shape and uses the same arrival transition across pages as Work and Playground.

- Preserve the current single-bounce arrival trajectory. Hold the previous All Projects icon at its exact displayed position, size, and rotation until the incoming icon contacts it, then knock the old icon downward. Clip the old icon at the icon slot’s bottom edge throughout the transition, so it cannot paint over the padding below.

- Debug mode lives in `dev-mode.js` (`const DEV_MODE = true/false;` at the top) with styles in `dev-mode.css`; there is no UI toggle, so turn it on/off only when asked (`python3 tools/dev_order.py on|off`). While on, the Work and Archive grids show a red "Debug mode" label above the tag group, cards can be dragged or moved with black hover arrows on either side of the thumbnail, thumbnails don't navigate (chips still do), and the header has a "Cancel & leave" button that discards the arrangement and turns debug mode off. The arranged order is a draft that survives refreshes: `python3 tools/dev-server.py` (http://localhost:8000, allowed by the media CORS rules) stores it in `.dev-order.json`. When the user asks to close/exit debug mode (keeping the order), run `python3 tools/dev_order.py apply`, which writes the draft into the HTML card order and sets `DEV_MODE = false`; if there is no draft, the order was likely arranged without the dev server and lives only in that browser. DOM order in the HTML is the listing order; there is no year sorting.

- Floating screens in grid thumbnails share the `--thumb-screen-margin-block` token in `style.css` (`0.0803`, the gap above and below the screen as a share of the thumbnail's width). Desktop screens (Verso, Superformula, Flying Squirrels, Schneider, Superfast) match Superformula: the screen is 85% of the thumbnail width (`width: 100%; scale: 0.85`) and keeps its own aspect ratio, and the thumbnail uses `aspect-ratio: 1 / calc(0.85 * h / w + 2 * var(--thumb-screen-margin-block))`. Phone screens (Neurial Grotesk, TL;DR) wrap the video in `<div class="thumb-phone-screen">` inside the thumbnail. The wrapper keeps the thumbnail's ratio by sizing from container units (`height: calc((thumb h / w - 2 * var(--thumb-screen-margin-block)) * 100cqw)`, plus `aspect-ratio` set to the video's own ratio), and rounds the screen with `border-radius`, `overflow: hidden` and a mask; the video just fills it. Don't use thumbnail padding with `height: 100%` (Safari/Firefox ignore that percentage and the gaps disappear), and don't rely on `border-radius` or `clip-path` on the video itself (Safari leaves a playing video's corners square). Apply this to any new floating screen.

- Work case-study pages (Dino, Schneider, GVD, Adventurer, nijimu case study) open with their cover, before the title, framed like the Playground page thumbnail: `.img-casestudy-cover` is a wrapper `div` placed before `.case-study-header`, a full-width 16:9 stage inset by `--page-inline-space` under the nav, with a 0.5rem radius, the media contained (Dino and Adventurer cover-fit their 16:9 art) on a per-page background, and the title starting 30px below it (80px on `.cs-grid` pages). Like Playground thumbnails, it shows immediately instead of scroll-revealing. GVD's cover uses the video's own ratio (`3420 / 2160`) so the stage height fits the recording instead of cropping it to 16:9.

- Case-study grid: add `cs-grid` to a case study's `<main>` to lay it out on a 5-column grid (30px column gap, 80px row gap) with Playground's outer spacing (`margin: var(--nav-height) var(--page-inline-space) 64px`). All five case studies (Dino, Schneider, GVD, Adventurer, nijimu case study) use it. The cover spans the full row; everything else stacks vertically in the center three columns (2–4): each section's `h3`, then its content 1.3rem below. The header holds the overview: the title (`h1`), then a `.cs-section-body` with the subtitle (`h2`), the Role/Timeline/Tools info rows, then any description paragraph. There is no separate Overview section. Section headings scroll normally (not pinned). Wrap each section's content in `<div class="cs-section-body">` after its `h3`. Every `.cs-section-body` (header included) is a flex column with a 40px `gap`, and its direct children's margins are zeroed: spacing between them comes only from the gap, never from margins. The one exception: a `p` directly following another `p` sits 14px below it (`margin-top: calc(14px - var(--cs-body-gap))`, with `--cs-body-gap: 40px` on `.cs-section-body`). Info-row label/value pairs aren't affected. Info lists show one entry per row; from 960px up, labels (`.entry-header`) sit in grid column 2 and values start exactly on grid column 3 (`grid-template-columns: calc((100% - 60px) / 3 + 30px) minmax(0, 1fr)`). In the grid, breakout images (`.img-mockup`, `.wrapper-design-system`, etc.) stay inside the center columns, and Schneider/GVD drop their centered 90ch prose column. The header, `.project-caption` and its sections are column subgrids. Design-system body text rule: all body text that isn't a caption (paragraphs, list items, info-list values, problem cards, links inside them) uses one style, the same as the info-list values: 14px Geist, weight 400, normal line height, full opacity, color `--cs-body-color` (#E6E6E6, a slightly grayer white). The one exception: paragraphs following an `h4` (problem cards, product-highlight entries) sit at 60% opacity with a 20px bottom margin (except in problem cards, which keep no bottom margin), and the case-study subtitle (`.case-study-header > .cs-section-body > h2`) uses that same look (body text style at 60% opacity, spacing still from the header's gap), and `h4`s are slightly larger than body text (15px base vs 14px) and never bold (weight 400). Headings and info-list labels keep their own styles. Captions (`.floating-caption` text and `figcaption`) match the landing page's card captions (`.card-text`) in size and weight but use Geist: weight 400, normal line height, full opacity, but at 12.75px and in a lighter gray (`--cs-caption-color`, #8C8C8C, instead of the landing page's #666). Media captions (`.floating-caption`) stay centered and sit 20px under their media (the parent's row gap and the media's bottom margin are zeroed), and its box fits the text height (no padding, no paragraph margin). Every media caption uses the same markup, `<div class="floating-caption"><p class="floating-caption-details">…</p></div>` after the media inside a `.captioned-item` (Dino's Results captions were converted from bare `<p>`s). Images and videos in `.product-highlight-entries`, and every image, video or image frame (e.g. `.wrapper-design-system`, `.outcome-poster-pair__images`) spanning the full content columns, have 8px corners, matching the Results images. Add new full-width media or frames to that rule. Section `h3`s and info-list labels (`.entry-header`) share one style: 1rem Geist, weight 400, no uppercase, in the page's heading color (`--cs-accent`, default #8A8FE5; Dino uses #858BEA: the default's hue and lightness, very slightly more saturated. "Brighter" means lighter, not more saturated). Each case study has its own theme color, set as `--cs-accent` on a per-project class on `<main>` (e.g. `.dino-project`, `.adventurer-project`) in `style-project.css`: Adventurer is #7BA871. Problem-list items (`.list-case-study-problems li`) are soft cards: a faint gray fill (`rgba(153,153,153,0.12)`), a barely visible 1px border (`rgba(153,153,153,0.12)`), 0.5rem radius, no left accent rule. Stacked media, product-highlight items and list entries inside a section sit 40px apart (`row-gap: 40px` on their flex/grid containers); Problem cards (`.list-case-study-problems`) are the exception: on every case study they always sit 14px apart. Each problem card's `h4` starts inline with its number (`01`, `02`… from a CSS counter on `h4::before`) in Geist Mono (loaded with Geist from Google Fonts), at the heading's size, in the page's `--cs-accent`, 8px before the heading text. Case-study videos autoplay without native controls (the `<noscript>` fallbacks keep `controls`). Every text size on `cs-grid` pages (title, labels, body, captions, `h4`s, GVD screen labels, Dino's see-all button) is written as `calc(<base> * var(--cs-text-scale))`; the scale is 1 below 960px and 15/14 from 960px up, so all case-study text runs slightly larger on wider screens (body 14px → 15px, captions 12.75px → ~13.7px). Use the scale for any new text size. Under 960px everything stacks in one column. The fixed section rail (`case-study-toc-enabled`) is left off `cs-grid` pages because it would overlap the content.

- Grid thumbnail corner radii are relative to the thumbnail's width (`cqi`), tuned at a 1270px viewport (Work thumbnail 603px wide). `[data-project-grid] > .card` and its `.card-thumbnail` are `container-type: inline-size` so this resolves. Every thumbnail frame shares `--radius-thumbnail` (`1.393cqi`, 8.4px at 1270) and every floating desktop screen shares `--radius-desktop-screen` (`1.857cqi`, 11.2px before its 0.85 scale). Floating phone screens (Neurial Grotesk, TL;DR) set their own `cqi` radius per card (currently both `4.643cqi`, 28px at 1270); they don't have to match. Don't use rem/px/vw radii on new grid thumbnails or screens.

- The fullscreen page loader plays once per browser tab. Any later visit to a hub page in that tab, reloads included, skips it (`hub-session.js` marks the page warm in `sessionStorage`). A new tab or session gets the full intro again.

- No case study page ends with the About section/drawer. Like Playground project pages, `main` (64px bottom margin) is followed directly by `<hr>` and the footer, and nav About links point to `index.html#about`.

- Case-study typeface is Geist (loaded from Google Fonts via a `<link>` in each case study's `<head>`, after `fonts.css`) for the title, subtitle, headings, labels and body text. Media captions (`.floating-caption` text, `figcaption`) use Geist too.

- Card titles (`.work-title` on index and archive) are 12% larger than the surrounding card text: `font-size: 1.12em` in `style.css` (14px → 15.68px), and `calc(0.875rem * 1.12)` under 960px in `responsive.css` (12.25px → 13.72px).

- GVD's redesign highlights show each before/after pair as a stack of two cards (`.gvd-compare` inside `figure.gvd-redesign-pair[data-compare-state]`, screens tagged `data-compare-version="after|before"`). Both screens share one spot at the same size and position (no scale, offset or dimming on the hidden one); the shown version sits in front. Segmented tabs, After first then Before (`.gvd-compare-switch`, two buttons with `aria-pressed` and a sliding highlight; the user tried a toggle switch and preferred tabs), replace the per-screen captions. They sit 20px under the stack, aligned to the left of the content column. The group has no padding or border, so the selected tab's highlight runs flush to its edges; each tab is padded 4px 12px. A tab brings that card to the front with a lift-and-cross animation (it rises 8%, crosses in front halfway, settles, while its opacity eases from 30% to 100% over the whole transition with `ease`) (`gvd-compare.js`, styles in `style-project.css`). After is shown by default. Reduced motion skips the animation.
