# Portfolio media loading and R2

`media-loader.js` loads artwork near the viewport, attaches video sources with
`preload="none"`, and plays automatic loops only while visible. Videos pause when
filtered out, scrolled away, or the browser tab is hidden. Manual pauses are
preserved. Reduced-motion visitors see a poster and playback controls instead of
automatic loops. Lightweight poster frames remain in `assets/media-posters/`.

`media-config.js` currently selects **local assets**. No R2 account, bucket,
DNS records, or live deployment has been changed. Cloudflare activation requires
the account owner to complete the following setup.

## One-time Cloudflare setup

1. In Cloudflare, enable R2 and create a **Standard** storage bucket, such as
   `ncwei-media`. Review the account's billing terms when enabling R2.
2. Add `ncwei.com` to Cloudflare DNS if it is not already there. On the free DNS
   setup this normally involves changing the nameservers at your registrar;
   first copy and verify all existing website and email DNS records. Keep the
   existing website records pointing at GitHub Pages.
3. In the bucket's **Settings → Custom Domains**, connect `media.ncwei.com` and
   wait until it is Active. Connect it through R2's settings, not by pointing a
   CNAME at an `r2.dev` URL. The `r2.dev` endpoint is for testing, not production.
4. In the bucket's **Settings → CORS Policy**, paste `tools/r2-cors.json`. This
   allows the website's canvas-based Pictogram rendering and image color sampling.
   Add any extra preview origins you use. Apply CORS before uploading/caching.
5. Under R2 API tokens, create **Object Read & Write** credentials limited to this
   bucket. Note your Cloudflare account ID and the R2 Access Key ID / Secret
   Access Key. Keep secrets out of chat, Git, and website JavaScript.
6. Install AWS CLI v2 from AWS if needed, then enter those credentials
   interactively. The official installer includes its own runtime, avoiding
   Homebrew Python/macOS library mismatches such as `pyexpat` missing
   `_XML_SetAllocTrackerActivationThreshold`:

   ```sh
   curl -fsSL https://awscli.amazonaws.com/v2/install.sh -o /tmp/ncwei-aws-install.sh
   bash /tmp/ncwei-aws-install.sh
   python3 tools/r2-media.py configure
   ```

   Use `auto` for the default region and `json` for the output format. The CLI
   stores the credentials outside this repository. Do not use AWS account keys;
   these must be the credentials generated by R2.

   The project script prefers `~/.local/bin/aws` (the official user-local
   installation) when it exists, even if your shell's `aws` still points to
   Homebrew. `configure` and `upload` use the same executable. You can select a
   different executable explicitly with the `NCWEI_AWS_CLI` environment variable.

## Upload and activate

Run from the repository root. Replace the account and bucket placeholders.

```sh
python3 tools/r2-media.py plan
python3 tools/r2-media.py upload --account-id YOUR_CLOUDFLARE_ACCOUNT_ID --bucket ncwei-media
python3 tools/r2-media.py activate --base-url https://media.ncwei.com
```

`plan` inventories only the media referenced by managed HTML attributes. It
excludes unused originals, asset-bin, scripts, fonts, icons and local posters.
`upload` creates content-fingerprinted object keys with the correct media types
and a one-year immutable cache lifetime. It never deletes bucket contents.
Changing an asset generates a new URL on the next upload/activation.

`activate` checks every public file's size, MIME type and CORS response, plus byte
range support for videos. It changes `media-config.js` only when all checks pass.
A failure leaves the previous configuration intact. You can run `verify` with the
same `--base-url` at any time. The browser falls back to the original local file
on a CDN loading error; retain local assets until a separate cleanup is planned.

If activation says the hostname cannot be resolved (`nodename nor servname
provided, or not known`), check **R2 → your bucket → Settings → Custom Domains**.
`media.ncwei.com` must be connected there and show **Active**; adding `ncwei.com`
to Cloudflare alone does not create this media subdomain. Use the exact domain
you connected in `--base-url`. After its DNS is working, rerun only `activate`
if the upload command already finished successfully.

If the domain is Active and public DNS resolves it but your Mac/network still
reports it missing, use:

```sh
python3 tools/r2-media.py activate --base-url https://media.ncwei.com --public-dns
```

This uses Google's DNS-over-HTTPS service for this verification's media hostname
only, retaining normal TLS certificate checks. It does not change macOS DNS
settings. Browser requests still use the browser/network's DNS settings; local
asset fallback remains available until that resolver catches up.

The verifier identifies itself as `NCWeiMediaVerifier` because Cloudflare's
Browser Integrity Check may reject Python's default request identity with HTTP
403 / error 1010. Both metadata and video-range checks use this identity. If a
403 still occurs, the error includes a Cloudflare Ray ID to look up in Security
Events. There is no need to grant broader R2 token permissions for public checks.

HTTP 404 means the requested object URL is missing. Wait for the upload command
to print **Upload finished** before activating. If uploading reported an error,
resolve that error first. If uploading succeeded, confirm that the custom domain
is attached to the same bucket specified by `--bucket`.

Preview at `http://localhost:8000` with:

```sh
python3 -m http.server 8000
```

Check work filters, scrolling through case studies, native video controls,
Pictogram rendering and the Nijimu collage on desktop/mobile before deploying
the website files through your normal GitHub Pages workflow. In browser Network,
media URLs should point to the custom domain after activation; distant videos
should not download until approached/played.

To restore local-only loading:

```sh
python3 tools/r2-media.py local
```

## Adding media later

Follow the HTML already in the project:

```html
<img data-media-src="assets/project/image.webp" width="1200" height="800"
     loading="lazy" decoding="async" alt="Describe the image">
<video data-media-src="assets/project/demo.mp4" data-media-autoplay
       data-media-poster="assets/media-posters/demo.webp"
       width="1280" height="720" preload="none" loop muted playsinline></video>
```

Use real intrinsic dimensions to reserve layout space. Add a local `<noscript>`
fallback, as existing pages do. Use `data-media-srcset` for responsive image
sources, with spaces in filenames URL-encoded. Leave `data-media-autoplay` off
for click-to-play videos and add `controls`. Keep scripts in this order:
`media-config.js`, `media-loader.js`, then existing page scripts. New assets that
are not in the verified R2 mapping continue to work locally until uploaded.

R2 serves the original video bytes; it does not compress them or provide adaptive
streaming. This implementation does not re-encode or reduce original video
quality, and does not remove files from Git history.
